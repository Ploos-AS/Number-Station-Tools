# M4.2 — A-B loop regions

M4.2 adds temporary A-B loop regions to the local signal workbench.

## Scope

For managed recordings, the recording archive now provides per-recording controls to:

- set loop start (A) at the current playback position
- set loop end (B) at the current playback position
- enable or disable A-B repeat
- clear the temporary loop region
- visualize the selected loop interval across waveform and mini-spectrogram previews

When looping is enabled and playback reaches B, the browser seeks back to A. If playback is outside the selected region when looping is enabled, it is moved to A.

## Interaction

M4.2 reuses the M4.1 seek surfaces. The operator can click or drag on the waveform or mini-spectrogram to position playback, then press Set A or Set B. The selected region is highlighted directly on both preview tracks.

A valid loop requires B to be after A. Changing A or B disables an active loop until it is explicitly enabled again.

## Persistence and privacy

A-B regions are browser-session state only. They are not written to `recordings.json`, do not modify recording metadata, and do not alter the managed audio file.

Playback continues to use the local `/api/recordings/{id}/stream` endpoint with HTTP byte-range support. No audio, loop state, or analysis metadata is sent to an external service.

## Qualification

The Go test suite verifies that the embedded frontend includes the A/B controls, loop toggle, rewind-to-A behavior, region styling hook, and script wiring in `index.html`.
