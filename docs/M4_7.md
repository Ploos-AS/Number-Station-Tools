# M4.7 — Cross-recording annotation search

M4.7 adds a local annotation index across the complete recording archive.

## Scope

- `GET /api/annotations?q=&type=&limit=` searches saved annotation type, label and notes.
- Results include the annotation plus recording ID, observation ID, path, format, duration and managed/local status.
- Type filtering uses the M4.6 fixed vocabulary.
- Empty `q` is allowed, so the endpoint can act as a bounded cross-recording annotation index.
- Default result limit is 50; accepted limits are 1–200.
- Older annotations without a stored type are returned as `other`.
- The web workbench adds a global Annotation index panel.
- Clicking a result scrolls to the matching recording and seeks managed playback to the annotation start timestamp when an audio player is present.
- Search remains local to the appliance. There is no external provider, AI service or API key.

## Persistence

M4.7 does not add a new persistence structure. The index is derived from the existing `recordings.json` recording and annotation data on each request.

## Qualification

Regression coverage verifies cross-recording text/type search, result context, API routing, and the embedded frontend jump/seek path. Standard CI remains `gofmt`, `go test ./...`, `go vet ./...`, Go build and OCI container build.
