# M3.8 — Fingerprint clustering and duplicate detection

M3.8 builds on the local 32-bin signal fingerprints introduced in M3.7.

## Scope

- Cluster recordings whose fingerprint cosine similarity meets a configurable threshold.
- Default threshold: 98%.
- Exclude singleton recordings from cluster results.
- Sort larger clusters first for review.
- Report the minimum pairwise similarity inside each cluster.
- Flag an exact file duplicate when two or more cluster members share the same non-empty SHA-256.
- Expose `GET /api/recording-clusters?threshold=98`.
- Add a local web panel for refreshing clusters and adjusting the threshold.

## Semantics

Fingerprint similarity is evidence of signal resemblance, not proof that two transmissions are identical. Exact duplicate status is reserved for matching SHA-256 file content. A cluster can therefore represent a repeated transmission, a near-duplicate capture, or recordings with a very similar spectral profile.

Clustering is implemented as connected components over pairwise fingerprint matches at or above the threshold. This means two members in one cluster may have a direct pairwise score below the threshold when both are linked through another member; `minimum_score` exposes the weakest pair in the resulting cluster.

## Constraints

- No AI or external service.
- No API key.
- No audio re-decoding during cluster queries; persisted fingerprints are used.
- Recordings without fingerprints are ignored.
- Existing FLAC behavior is unchanged because FLAC sample decoding is still intentionally out of scope.
