# M5.1 — Safe portable archive restore

M5.1 adds a conservative restore path for the verified M5.0 `tar.gz` archive.

## API

`POST /api/recording-archive/import`

The request body is the raw M5.0 gzip-compressed tar archive. The endpoint returns a JSON result containing imported recording/annotation counts plus duplicate, conflict and unmatched counts.

## Verification before commit

The importer stages archive content under the configured audio directory and validates it before persistent metadata or final audio paths are changed.

- gzip and tar must parse cleanly.
- Only regular files are accepted; symlinks and special entries are rejected.
- Entry names must be exactly `manifest.json` or `audio/<basename>`; traversal and nested paths are rejected.
- Duplicate archive entries are rejected.
- The compressed HTTP request is limited to 1 GiB.
- Expanded archive content is limited to 2 GiB, individual audio entries to 256 MiB, the manifest to 16 MiB and the manifest to 10,000 recording items.
- The manifest must use recording bundle version 1.
- Every managed recording must reference the exact managed `audio/<basename>` entry.
- File size and SHA-256 must match the manifest.
- WAV/FLAC signatures and audio metadata are revalidated.
- Derived waveform, frequency, spectrogram and fingerprint data are rebuilt locally from restored audio instead of trusting exported preview payloads.
- Extra unreferenced audio entries are rejected.

## Collision policy

M5.1 never blindly overwrites an existing recording or managed audio file.

- A recording ID that already exists with equivalent portable metadata is treated as a duplicate. Missing annotations may still be merged after validation; identical annotations are suppressed.
- A recording ID that exists with different metadata is counted as a conflict and is not modified.
- A new managed recording whose destination filename already exists is counted as a conflict and is not imported.
- Imported annotations receive new local annotation IDs.
- Recordings whose referenced observation does not exist locally are reported as unmatched and are not imported.

The restore writes staged audio into final paths before saving metadata, and rolls those moves back if persistence fails. Existing files are never replaced.

## Scope

M5.1 restores recording metadata, annotations and managed audio from M5.0 archives. It does not create missing stations or observations, restore cluster-review state, overwrite existing recordings, transcode audio, or contact external services.

Core restore remains local-first and requires no SDR, AI service or API key.
