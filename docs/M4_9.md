# M4.9 — Portable recording and annotation manifest

M4.9 adds a versioned metadata-only recording bundle for archival, provenance and later transfer workflows.

## Scope

- `GET /api/recording-bundle` returns a downloadable JSON manifest.
- Manifest version is `1`.
- Every recording entry includes the persisted recording metadata that is meaningful for portability, including IDs, observation linkage, path/name metadata, format, size, duration, sample rate, channels, SHA-256, notes and managed/original-name state.
- Saved timestamp annotations are embedded under their recording and normalized to the current annotation type vocabulary.
- Recording entries and annotations are emitted in deterministic order.
- SHA-256 values are normalized to lowercase.

## Explicitly excluded

M4.9 does not copy or embed audio files. It also excludes derived waveform, frequency-preview, spectrogram and fingerprint byte arrays from the manifest. Those payloads are reproducible local analysis artifacts rather than portable source/provenance metadata.

The bundle is export-only in M4.9. Import/restore of recording manifests is intentionally deferred so matching, collision handling and managed-file lifecycle can be designed and qualified separately.

## Local-first behavior

The export is generated entirely from the local recording store. No receiver, SDR, API key, cloud service or AI service is required, and exporting the manifest does not mutate recordings, annotations or audio files.
