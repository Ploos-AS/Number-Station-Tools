# M5.0 — full portable archival bundle

M5.0 turns the M4.9 metadata manifest into a self-contained archival export for
managed recordings.

## Archive format

`GET /api/recording-archive` returns `number-station-archive.tar.gz`.

The archive contains:

- `manifest.json` — the versioned M4.9 recording/annotation manifest
- `audio/<managed filename>` — each managed WAV/FLAC file that passes preflight

External metadata-only recordings remain represented in `manifest.json`, but no
external path is read or copied into the archive.

## Integrity and path rules

Before the HTTP archive response starts, every managed recording is checked:

1. the metadata path must be exactly `audio/<basename>`;
2. the source must exist under the configured managed audio directory;
3. `Lstat` must report a regular file, so symlinks and special files are rejected;
4. the stored size must match when a size is present;
5. a 64-character stored SHA-256 is required;
6. the actual file SHA-256 must match the stored checksum.

Any failed check rejects the entire archive export. There is no partial-success
mode and no fallback to arbitrary paths.

## Manifest behavior

The embedded manifest keeps the M4.9 semantics:

- recording and observation linkage
- format, path/original filename, size, duration, sample rate and channels
- SHA-256, notes and managed state
- nested normalized annotations
- deterministic recording/annotation ordering
- derived waveform, frequency, spectrogram and fingerprint byte arrays omitted

## Non-goals

M5.0 does not:

- import or restore a full archive
- modify or delete audio files
- transcode recordings
- follow symlinks
- read external metadata-only recording paths
- depend on cloud services, AI, API keys or an SDR

Archive restore/import is intentionally deferred so collision policy, observation
linkage and managed-file lifecycle can be qualified independently.
