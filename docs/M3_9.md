# M3.9 — Cluster review and classification

M3.9 adds a local human-review layer on top of M3.8 fingerprint clustering.

## Scope

Each active fingerprint cluster can be classified as one of:

- `same transmission`
- `same station`
- `false positive`
- `duplicate capture`

A review can also contain an optional free-text note (maximum 2000 characters).
The server records the review timestamp in UTC.

## Stable review identity

Cluster review identity is derived from the sorted recording IDs in the cluster.
The resulting cluster ID is a truncated SHA-256 digest of that member set.

This means:

- member ordering does not change the cluster ID;
- changing cluster membership does change the cluster ID;
- a review therefore only attaches to the exact member set that was reviewed;
- threshold changes that alter membership cannot silently reuse an unrelated review.

## Persistence

Reviews are stored in the existing recording metadata JSON under
`cluster_reviews`. Existing `recordings.json` files without that field remain
valid and are normalized to an empty review list when opened.

Each persisted review contains:

- cluster ID;
- classification;
- optional notes;
- the reviewed recording IDs;
- UTC review timestamp.

## API

- `GET /api/recording-clusters?threshold=98` returns active clusters and their
  current review, when one exists.
- `PUT /api/recording-clusters/{id}/review?threshold=98` stores or replaces a
  review for an active cluster. The request body contains `classification` and
  optional `notes`.
- `DELETE /api/recording-clusters/{id}/review` removes a stored review.

The PUT endpoint verifies that the supplied cluster ID exists at the requested
threshold before saving a review.

## Web UI

The Fingerprint clusters panel now shows whether each cluster is reviewed or
unreviewed, exposes the four classifications, accepts notes, displays the UTC
review time, and allows a review to be updated or cleared.

## Local-first boundary

Cluster review is deterministic and local. It does not use AI, an external
classifier, API keys, cloud storage, or external services.

## Qualification

M3.9 is qualified by the repository CI gate:

- `gofmt` clean;
- `go test ./...`;
- `go vet ./...`;
- Go binary build;
- OCI container build.

Regression coverage includes persisted review reload, classification validation,
stable cluster IDs across member ordering, cluster-ID changes when membership
changes, and review deletion.
