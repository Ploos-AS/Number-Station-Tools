# M5.5 — Persistent restore receipts

M5.5 adds a local audit trail for successful portable archive restores.

## Scope

- Persist one receipt after each successful full restore.
- Persist one receipt after each successful selective restore.
- Keep receipt data separate from `recordings.json` in `<recordings path>.restore-receipts.json`.
- Return the newly persisted receipt in the restore API response.
- Expose recent receipts through `GET /api/recording-archive/receipts?limit=50`.
- Keep the receipt API read-only; M5.5 does not add receipt deletion or editing.

## Receipt fields

Each receipt contains:

- generated receipt ID
- UTC timestamp
- restore mode: `full` or `selected`
- imported recording count
- imported annotation count
- duplicate/conflict/unmatched counts
- selective-policy skip count when applicable
- M5.4 plan token for selective restore
- sorted selected recording IDs for selective restore

Receipts do not contain archive bytes, audio bytes, waveform/spectrum payloads, fingerprints, annotations themselves, or other duplicated recording content.

## Persistence

The receipt store uses the same atomic temporary-file-and-rename pattern as the other JSON stores and mode `0600`. It is initialized lazily from the recording-store path, so no new environment variable is required.

A restore is validated and committed by the existing M5.1–M5.4 path first, then the receipt is persisted. If receipt persistence fails after a successful restore, the API reports this explicitly rather than claiming that the audit record exists. M5.5 does not attempt to undo an already committed restore solely because the subsequent audit write failed.

## API

### List receipts

`GET /api/recording-archive/receipts?limit=50`

- default limit: 50
- allowed range: 1–200
- newest receipts first

### Restore responses

Successful full and selective restore responses retain their existing top-level result fields and add:

```json
{
  "receipt": {
    "id": "...",
    "at": "2026-09-08T...Z",
    "mode": "selected",
    "plan_token": "..."
  }
}
```

Existing clients that ignore unknown JSON fields remain compatible.

## Non-goals

M5.5 does not add remote logging, external SIEM integration, signed receipts, receipt deletion/editing, archive payload retention, or user identity/authentication. Those can be considered separately without weakening the local-first restore path.
