# M4.6 — annotation categories

M4.6 adds a fixed local category vocabulary to recording annotations so a workbench can distinguish common numbers-station events without introducing external classification services.

## Categories

Annotations may use exactly one of:

- `call-up`
- `station ID`
- `message`
- `tone`
- `noise`
- `fade`
- `other`

Older annotations without a `type` field are interpreted as `other`, so existing `recordings.json` files remain usable without migration.

## Workbench

The annotation create/edit form includes a type selector. Saved annotations display a type badge and waveform/spectrogram markers receive type-specific visual classes. The per-recording annotation view can be filtered by type; filtering affects both the list and visible timeline markers.

Direct timeline bookmarks created by right-click or the `B` shortcut use `other` by default and can be reclassified through Edit.

## API and persistence

The existing annotation endpoints are unchanged. The annotation JSON object gains an optional `type` field. The server normalizes a missing/blank value to `other` and rejects values outside the fixed category set.

Data remains local in `recordings.json`; no SDR, API key, AI model, or external service is required.

## Qualification

Standard CI must pass:

- `gofmt`
- `go test ./...`
- `go vet ./...`
- Go build
- OCI container build

Regression coverage verifies category validation/defaulting, API persistence, the type selector/filter, and type-specific marker styling.
