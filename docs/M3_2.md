# M3.2 — Managed audio ingest

M3.2 lets Number Station Tools store local WAV/FLAC captures in addition to external recording metadata.

## Scope

- multipart upload endpoint for WAV/FLAC files
- server-generated storage names only
- local storage under `/data/audio`
- configurable storage root through `NUMBER_STATION_TOOLS_AUDIO_DIR`
- 256 MiB per-upload limit
- WAV `RIFF...WAVE` and FLAC `fLaC` signature checks
- automatic byte size and SHA-256 calculation
- recording metadata marked as `managed`
- original client filename retained as display metadata only
- safe download endpoint for managed files
- upload UI linked to observations
- existing external recording metadata remains supported

## API

- `POST /api/audio` — multipart form with `observation_id`, `file`, optional `notes`
- `GET /api/recordings/{id}/file` — download a managed recording

## Safety properties

User-provided filenames are never used as server storage paths. Managed files are stored with server-generated IDs and a validated `.wav` or `.flac` suffix. Downloads resolve only managed metadata and only by the stored basename inside the configured audio directory.

M3.2 intentionally does not delete audio when ordinary recording metadata is deleted. Destructive managed-file cleanup should be an explicit later operation.

## Qualification

M3.2 is complete when `gofmt`, `go test ./...`, `go vet ./...`, the Go build and OCI container build pass in CI.
