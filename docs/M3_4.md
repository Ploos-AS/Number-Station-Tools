# M3.4 — Waveform preview metadata

M3.4 adds a compact signal preview for managed PCM WAV recordings.

## Scope

- build a 128-bin peak-amplitude envelope during managed WAV ingest
- store the envelope in recording metadata as values from 0 to 255
- expose the preview through the existing recording JSON API
- render the preview in the recording archive without fetching the full audio file
- keep managed derived fields immutable during ordinary metadata edits

## WAV support

The preview parser is dependency-free and reads PCM WAV data directly from RIFF/WAVE chunks.

Supported preview sample formats:

- unsigned 8-bit PCM
- signed 16-bit PCM
- mono or multi-channel audio

For each time bin, the maximum absolute amplitude across all frames and channels is stored.

## FLAC behavior

FLAC remains fully supported for managed ingest and automatic duration/sample-rate/channel metadata, but M3.4 does not synthesize a waveform for compressed FLAC audio. Producing a true amplitude envelope requires decoding the FLAC frames, which is intentionally deferred rather than adding a codec/runtime dependency in this milestone.

## Storage

The waveform is embedded in `/data/recordings.json` with the recording entry. A preview is at most 128 bytes of sample values before JSON overhead, so it remains small relative to the managed audio file.

## Integrity

For managed recordings, ordinary metadata updates preserve server-derived fields:

- managed flag
- stored path
- original filename
- format
- size
- duration
- sample rate
- channels
- SHA-256
- waveform preview

This prevents UI/API metadata edits from corrupting managed-file provenance.

## Qualification

M3.4 is complete when:

- `gofmt` passes
- `go test ./...` passes
- `go vet ./...` passes
- Go build passes
- OCI/container build passes
- waveform generation is covered by tests
- managed ingest persists the waveform preview
