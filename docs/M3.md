# M3 — Recording metadata foundation

M3 adds a local metadata layer for signal recordings linked to observations. This milestone deliberately does not ingest, upload, stream or manipulate audio files; it establishes the integrity model first.

## Scope

- recording metadata linked to an existing observation
- supported archival formats: WAV and FLAC
- path / filename metadata
- byte size
- duration in milliseconds
- sample rate
- channel count
- optional SHA-256 checksum
- free-form notes
- create, update, delete and newest-first list operations
- atomic JSON persistence
- observation-reference validation

## Storage

The recording metadata store is separate from the existing observation database so the audio archive can evolve independently:

`/data/recordings.json`

M3 does not copy or open the referenced recording path. Paths are metadata only.

## Integrity

- `observation_id` must point to an existing observation.
- `path` is required.
- format must be `wav` or `flac`.
- numeric metadata cannot be negative.
- when supplied, SHA-256 must be exactly 64 hexadecimal characters.
- update preserves the recording ID.

## Qualification

M3 foundation is complete when:

1. `gofmt` passes.
2. `go test ./...` passes.
3. `go vet ./...` passes.
4. native Go build passes.
5. OCI container build passes.

## Next

M3.1 will expose this model through HTTP/API and the web UI, including recording entries on each observation. Actual audio ingestion and SDR capture remain later milestones.
