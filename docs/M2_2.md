# M2.2 — Maintenance and filtering

M2.2 makes the local catalogue maintainable instead of append-only.

## API

- `PUT /api/stations/{id}` updates a station while preserving its ID.
- `DELETE /api/stations/{id}` deletes an unreferenced station.
- `PUT /api/schedules/{id}` updates a schedule while preserving its ID.
- `DELETE /api/schedules/{id}` deletes a schedule.

Station deletion is intentionally blocked while observations or schedules reference the station. This prevents orphaned monitoring history.

## UI

The web interface can edit and delete stations and schedules. The schedule archive also has immediate client-side filtering across station name, frequency, mode, UTC times, weekdays and notes.

## Qualification

M2.2 requires the normal CI gates: gofmt, `go test ./...`, `go vet ./...`, native Go build and OCI container build. Regression tests cover edit/delete persistence and station-reference protection.
