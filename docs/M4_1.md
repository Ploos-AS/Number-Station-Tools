# M4.1 — Interactive seeking

M4.1 turns the M4.0 waveform and mini-spectrogram previews into interactive seek surfaces for managed recordings.

## Scope

- click waveform or spectrogram to seek to the corresponding relative playback position
- drag horizontally while the pointer is held to scrub through the recording
- touch/pointer input uses the same code path
- focused previews support keyboard seeking
  - Left/Right: 1 second
  - Shift+Left/Right: 10 seconds
  - Home: start
  - End: end
- the existing synchronized playback cursor follows all seeks
- ARIA slider metadata reports relative position and current/total time
- seeking changes only browser playback state; no recording metadata is modified

The feature is available only when a recording already has the M4.0 managed local player. External metadata-only recordings remain non-playable and therefore non-seekable.

## Architecture

Seeking is implemented entirely in the embedded web frontend. Pointer coordinates are normalized to a value from 0 to 1 across the preview width and converted to `audio.currentTime` using the browser-reported duration, with stored duration metadata as fallback.

No new server endpoint, transcoding layer, DSP dependency, API key or external service is required. M4.0 HTTP range streaming remains the transport used by the browser when seeking.

## Qualification

The Go test suite checks that the embedded playback frontend contains the pointer, keyboard, duration and ARIA seeking paths. Existing M4.0 server tests continue to qualify HTTP byte-range streaming and partial-content responses.
