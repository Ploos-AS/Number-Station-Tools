# M4.8 — annotation export/import

M4.8 adds portable, local annotation transfer without changing `recordings.json` storage or sending data to an external service.

## Export

`GET /api/annotations/export?format=json` downloads a versioned JSON bundle. Each annotation is exported with recording matching metadata: recording ID, path, optional SHA-256, and duration.

`GET /api/annotations/export?format=csv` downloads a flat CSV suitable for archival, spreadsheets, and offline analysis. CSV is export-only in M4.8.

## Safe JSON import

`POST /api/annotations/import` accepts the versioned JSON export format. The request body is limited to 8 MiB and a bundle may contain at most 10,000 items.

Recording matching is intentionally conservative:

- if the exported recording has a SHA-256, import requires exactly one local recording with that SHA-256;
- without SHA-256, both recording ID and path must match;
- path-only matching is never accepted;
- ambiguous or missing matches are reported as `unmatched` and are not imported.

Imported annotations receive new local annotation IDs. Existing annotations with the same recording, start/end, type, label, and notes are counted as `duplicates` and skipped.

Every matched annotation is validated against the local recording, including timestamp bounds and the M4.6 annotation type vocabulary. A validation failure aborts the import before new annotations are persisted. The final write uses the existing atomic recording-store save path.

The result is returned as:

```json
{
  "imported": 4,
  "duplicates": 2,
  "unmatched": 1
}
```

## Web workbench

The Annotation transfer panel provides direct JSON and CSV downloads plus JSON file import. The browser performs only a basic JSON/file-size precheck; authoritative matching and validation remain server-side.

M4.8 requires no API key, cloud service, AI model, or SDR integration.
