# M3.5 — Frequency preview metadata

M3.5 adds a compact frequency-domain preview for managed PCM WAV recordings.
The goal is to surface useful signal structure in the recording archive without
requiring ffmpeg, ffprobe, an SDR, browser-side audio decoding, or downloading
the full recording.

## Scope

- Analyze managed PCM WAV during ingest.
- Produce 64 normalized magnitude bins from 0 Hz to the Nyquist frequency.
- Analyze several windows spread across the recording and retain the strongest
  magnitude seen per frequency bin.
- Store the preview in recording metadata as `frequency` plus
  `frequency_max_hz`.
- Preserve these server-derived fields during ordinary recording metadata edits.
- Render the frequency preview in the recording archive using the JSON metadata
  already returned by `/api/recordings`.
- Keep FLAC ingest working unchanged; compressed FLAC does not receive a
  frequency preview until a decoder is introduced.

## Analysis model

The analyzer supports the same uncompressed PCM subset as the waveform preview:
8-bit and 16-bit integer PCM, mono or multi-channel. Multi-channel audio is mixed
to mono for analysis. A Hann window is applied before a small dependency-free DFT.
The result is normalized to unsigned 8-bit magnitude values for compact JSON
storage and display.

This is a preview, not a calibrated spectrum analyzer. It is intended for quick
visual comparison and spotting dominant tones or broad signal regions.

## Qualification

The regression suite includes a synthetic 1 kHz PCM WAV tone and verifies that
the dominant preview bin lands near 1 kHz. Existing ingest, waveform, metadata,
API, vet, binary-build and container-build gates remain authoritative.
