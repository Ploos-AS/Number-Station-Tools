# M4.3 — recording bookmarks and timestamp annotations

M4.3 adds persistent local annotations to recording analysis.

## Scope

A recording annotation belongs to exactly one recording and can represent either:

- a point bookmark with `start_ms`, or
- a time interval with `start_ms` and `end_ms`.

Each annotation has a required short label and an optional local note. Typical labels include `call-up`, `station ID`, `message starts`, `tone change`, or any operator-defined wording.

Annotations are stored in the same atomic `recordings.json` data file as recording metadata and cluster reviews. Existing files remain backward compatible because the new top-level `annotations` collection is optional when loading.

## API

- `GET /api/recordings/{id}/annotations`
- `POST /api/recordings/{id}/annotations`
- `PUT /api/recordings/{id}/annotations/{annotationID}`
- `DELETE /api/recordings/{id}/annotations/{annotationID}`

Example payload:

```json
{
  "start_ms": 12500,
  "end_ms": 18400,
  "label": "Station ID",
  "notes": "Clear voice ID after tone sequence"
}
```

`end_ms` may be omitted or zero for a point bookmark. When present it must be greater than `start_ms`. If the recording has a known duration, both timestamps must fit within that duration.

Labels are limited to 120 characters and notes to 2000 characters.

## Workbench UI

Each recording entry gets a local annotation panel. The operator can:

- enter start/end milliseconds manually,
- copy the current audio position into Start or End,
- save a point or interval annotation,
- click an existing annotation to seek playback to its start,
- delete an annotation.

The annotation layer works for metadata-only recordings as well; current-position controls and seek actions naturally require a managed playable recording.

A-B loop regions from M4.2 remain temporary browser state. M4.3 annotations are the persistent layer and are not automatically coupled to a loop region.

## Integrity

Deleting a recording also deletes its annotations in the same recording-store save. Deleting recording metadata still does not delete the managed audio file itself; that lifecycle behavior remains unchanged from earlier milestones.

No AI, cloud service, external API, transcoding, or SDR integration is required.
